# ระบบ Login และสิทธิ์ผู้ใช้ (Auth & Roles)

> กลับไปหน้าหลัก: [../CLAUDE.md](../CLAUDE.md) · โครงสร้างตารางที่เกี่ยวข้อง: `Users`, `MemberTiers`, `UserAddresses` ดูที่ [database.md](./database.md)

แบ่งผู้ใช้เป็น 3 ระดับ:

1. **Super Admin** — ดูแลระบบภาพรวมทั้งหมด จัดการ tenant ทั้งหมด (ถ้าเปิดโหมด marketplace หลายร้าน)
2. **Tenant Admin** — เจ้าของ/แอดมินร้าน จัดการสินค้า, ออร์เดอร์, ธีม, บัญชีรับโอน, การแจ้งเตือน, และตั้งค่าระดับสมาชิก (`MemberTier`) ของร้านตัวเอง
3. **Member (สมาชิก)** — ลูกค้าที่สมัคร/ล็อกอิน แบ่งเป็นหลายระดับได้ (`MemberTier` เช่น ทั่วไป/VIP/VVIP) แต่ละระดับได้สิทธิ์ต่างกัน:
   - ดึงที่อยู่จัดส่ง default จาก `UserAddress` มาเติมในฟอร์ม checkout อัตโนมัติ (ยังแก้ไขได้ก่อนยืนยัน) — สิทธิ์นี้เท่ากันทุกระดับ
   - รับส่วนลด/จัดส่งฟรีตามที่ตั้งค่าไว้ใน `MemberTier` ของตัวเอง (แต่ละระดับกำหนดค่าต่างกันได้ เช่น ทั่วไปลด 3%, VIP ลด 8% + จัดส่งฟรี)
   - ดูประวัติการสั่งซื้อของตัวเองได้โดยไม่ต้องกรอกเลขออร์เดอร์ค้นหา

**Guest (ผู้เยี่ยมชมทั่วไป)** ไม่ต้องมี record ผู้ใช้ — สั่งซื้อได้ตามปกติผ่าน flow checkout เดิม (กรอกที่อยู่เอง, ไม่ได้ส่วนลด/จัดส่งฟรี) และควรมีปุ่มชวนสมัครสมาชิกระหว่าง checkout เช่น "สมัครสมาชิกเพื่อรับส่วนลด X%"

## ระบบระดับสมาชิก (MemberTier)

- แอดมินร้านสร้างระดับสมาชิกได้เองหลายระดับ ตั้งชื่อ, ส่วนลด, และเงื่อนไขจัดส่งฟรีของแต่ละระดับผ่านหน้า admin
- ทุกร้านต้องมี tier เริ่มต้น (`IsDefault = 1`) หนึ่งระดับ ที่สมาชิกใหม่ทุกคนได้รับอัตโนมัติตอนสมัคร
- การเลื่อนระดับสมาชิก (เช่น ตามยอดซื้อสะสม หรือแอดมินปรับเองเป็นรายคน) เป็น business logic ที่ทำเพิ่มได้ภายหลัง ไม่ผูกไว้ตายตัวใน schema — เก็บแค่ `User.MemberTierId` ปัจจุบันของแต่ละคน
- ตอนคำนวณยอด checkout ให้บันทึก tier ที่ใช้จริง ณ ตอนนั้นไว้ใน `Order.AppliedMemberTierId` ด้วย เพื่อให้ยอดในออร์เดอร์เก่าไม่เปลี่ยนถ้าแอดมินแก้ค่าส่วนลดของ tier ภายหลัง

## แนวทางการ implement

- ใช้ JWT หรือ session-based auth ก็ได้ ขึ้นกับ stack (เช่น NextAuth.js ถ้าใช้ Next.js)
- Middleware ตรวจ `Role` ก่อนเข้าหน้า admin (`tenant_admin`/`super_admin` เท่านั้น) และหน้าที่ต้องล็อกอิน (เช่น `/account`, ประวัติคำสั่งซื้อ)
- หน้า checkout ต้องเช็คว่า user ล็อกอินอยู่หรือไม่ ถ้าล็อกอิน: ดึง `UserAddress` ที่ `IsDefault = 1` มา pre-fill ฟอร์ม และคำนวณส่วนลด/ค่าส่งจาก `MemberTier` ปัจจุบันของ user นั้นก่อนแสดงยอดรวม (ดู flow เต็มที่ [checkout-and-payment.md](./checkout-and-payment.md))
- หน้า admin ต้องมีจุดจัดการ `MemberTier` (เพิ่ม/แก้ไข/ลบระดับ, ตั้งชื่อ, เปอร์เซ็นต์/จำนวนเงินส่วนลด, เปิด/ปิดจัดส่งฟรี, ยอดขั้นต่ำ, กำหนด tier เริ่มต้น) และจุดปรับ tier ของสมาชิกแต่ละคนได้เอง
